faq:
- question: Do credentials travel inside a Power Platform solution when exporting
    to another environment?
  answer: No. Solutions carry components and references only. The authorized connection
    with its credentials and consent must be created separately in each target environment.
- question: How can I automate connection reference mapping with pac solution import?
  answer: Generate a deployment settings file with pac solution create-settings, fill
    in the target connection mappings, and pass the file to pac solution import.
- question: Why is an imported flow failing even though the solution import succeeded?
  answer: A successful import only confirms the package was accepted. Missing, wrongly
    mapped or unauthorized connections can still keep dependent flows from running.

## TL;DR

Solutions move flows and connection references between environments, but never the authorized connections themselves. Before each import, create and sign in to the target connections, map every reference to the right identity, keep connection mappings separate from environment variables, and automate with Power Platform pipelines or a deployment settings file generated by pac solution create-settings. Validate flows with a functional test after import.

## Governance takeaway

- Makers: Keep flows and their connection references inside the release solution, name references clearly, and record connector, dependent components and target connection in an inventory before export.
- Admins/CoE: Define the pipeline deployment path, decide who owns production connections before release, and recheck mappings when owners change roles or leave.
- Security/Compliance: Treat deployment settings files as configuration, never store passwords in them, and restrict access to files that reveal internal environment details.
