## TL;DR

In Copilot Studio, an MCP tool continued showing “Let’s get you connected first” despite an active connection because “Credentials to use” was set to “End user credentials.” Switching the tool to “Maker-provided credentials” stopped the connection prompt and made the test agent work, while API key authentication and additional connections did not resolve it.

{% include curated-attribution.html %}

## Governance takeaway

Admins/CoE should test the MCP tool’s “Credentials to use” setting when an agent repeatedly sends users to Connection Manager despite an active connection. Security/Compliance should review whether maker-provided credentials are appropriate for the connector and usage scenario, because that setting means the agent no longer requires each user to connect; the source does not define the resulting access boundaries.
